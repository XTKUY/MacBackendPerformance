## 1. 项目概述

### 1.1 背景与问题

用户使用 M 芯片 Mac mini，在**关闭显示器**后返回时经常发现机身发烫，但打开活动监视器无法定位"休眠期间"是哪个进程导致的高占用。原因有两层：

1. **关闭显示器 ≠ 系统睡眠**。Mac 在插电关屏后，很可能并没有真正休眠，而是进入 dark wake（暗唤醒）状态，或被某个进程通过 App Nap / `PreventUserIdleSystemSleep` 断言阻止睡眠。
2. **唤醒后的瞬时快照丢失**。活动监视器只显示当前时刻的状态，无法还原"关屏后的几小时里谁在持续占 CPU/GPU"。

因此，本工具的目标不是"在休眠时采样"（真正休眠时所有进程都被挂起，无人占 CPU），而是**持续记录系统从"关屏前"到"唤醒后"全时间线的 CPU / 内存 / GPU / 电源状态**，事后按时间段聚合分析，定位热源进程。

### 1.2 项目目标

- 提供一个带 **TUI 的终端工具**，运行期间实时展示当前高占用进程与系统负载；
- 以 1–2 秒粒度持续采样 **CPU、内存、GPU、功耗、温度**，并记录**电源事件**（睡眠 / 唤醒 / 断言快照）；
- 数据持久化到 **SQLite**，支持按时间段回放与聚合分析（`report` 子命令）；
- 工具自身开销尽量低（目标：CPU < 0.5%，内存 < 30 MB），不污染被测数据；
- 单二进制分发，运行目标机器无需安装任何运行时或数据库。

### 1.3 非目标（本期不做）

- 不做跨平台（Intel Mac 无 IOReport GPU 通道，明确只支持 Apple Silicon）；
- 不修改系统电源设置（只观测、不干预）；
- 不做实时推送告警（列为后续扩展项）；
- 不提供 GUI。

## 2. 功能需求

### 2.1 数据采集

**进程级（核心需求）**

- PID、进程名；
- CPU 占用率（两次采样 delta 计算）；
- 内存占用（RSS / phys footprint）。

**系统级**

- 总 CPU 占用、内存 / Swap 用量；
- **GPU 活动率、GPU 频率、GPU 功耗（新增需求）**；
- CPU / GPU 温度、SoC 各域功耗（CPU / GPU / ANE / 整机）、系统热状态（thermal state）；
- 电源状态标签（awake / asleep / dark-wake 推断）。

**电源事件**

- 睡眠 / 唤醒事件（IOKit 通知），**记录进入睡眠的精确时间戳**，并保存睡眠前最后一批采样快照（用于确认系统实际睡了多久、睡前谁在高占用）；
- 电源断言快照（`pmset -g assertions`，仅在内容变化时落库）；
- dark wake 时段推断（可选，见 6.3）。

### 2.2 终端 TUI

- 实时进程 Top N 表（按 CPU / 内存 / PID 排序）；
- CPU / GPU / 内存趋势曲线（sparkline / block chart）；
- 电源事件日志与当前电源状态；
- 会话信息（开始时间、已采样数、数据库路径、工具自身开销）；
- **启动时选择采样间隔**（可自由设定，如 1s / 5s / 10s，也可用 CLI 参数预设）；
- **历史检查模式**：停止记录后打开已记录的数据库，按时间段浏览系统与单进程的性能曲线和明细数据（见 6.5）；
- 配色：catppuccin 主题（默认 mocha，可切换 latte / frappe / macchiato）；
- 键位：排序切换、进程面板开关、图表样式、主题切换、暂停采样、过滤、退出。

### 2.3 持久化

- SQLite（WAL 模式），按会话（session）划分数据；
- 采样表、电源事件表、会话表；
- 支持长时间运行（数据量估算见 6.7）。

### 2.4 报表分析

```text
neko-perf report --db <path> --from <ISO8601> --to <ISO8601> [--top 20] [--format table|csv|json|md]
neko-perf events  --db <path> [--from ...] [--to ...]
```

- 按时间段聚合每个进程的平均 / 峰值 CPU、总活跃样本数、出现时长；
- 展示该时段内的电源事件，区分"睡眠段 / dark wake 段 / 正常唤醒段"；
- 导出 CSV / Markdown / JSON，便于进一步分析。

### 2.5 CLI 参数

```text
neko-perf                          # 默认进入 TUI（启动时可交互选择采样间隔）
neko-perf daemon --db <path> --interval 5000 [--no-gpu]   # 无 TUI 后台采集
neko-perf inspect --db <path>      # 停止记录后，用 TUI 检查历史数据
neko-perf report --db <path> ...   # 事后静态聚合分析
```

主要参数：采样间隔（自由设定，如 5000ms）、进程采样间隔、Top N、数据库路径、GPU 开关、终端渲染开关。

## 3. 技术选型

### 3.1 语言选型：Rust

| 维度 | Rust | Python | Go |
| --- | --- | --- | --- |
| 工具自身开销 | 最低（无 GC、单二进制） | 较高（解释器 + GC） | 低 |
| 长期运行稳定性 | 高，可挂整晚 | 中 | 高 |
| TUI 生态 | ratatui 成熟 | textual / rich 成熟 | bubbletea 良好 |
| 打包分发 | 单二进制，零依赖 | 需运行时 / PyInstaller | 单二进制 |
| 开发速度 | 较慢 | 最快 | 快 |
| 本场景契合度 | ★★★（首选） | ★★ | ★★ |

**结论**：本项目是"长时间后台采样 + TUI + 事后分析"的观测工具，自身开销与稳定性优先，选择 **Rust**。

### 3.2 依赖清单

| crate | 用途 | 理由 / 备注 |
| --- | --- | --- |
| `ratatui` + `crossterm` | TUI 渲染 | 终端 UI 生态最成熟，支持表格、sparkline、自定义绘制 |
| `sysinfo` | 进程级 CPU / 内存枚举 | 跨平台，两次刷新取 delta 计算 CPU% |
| `macmon`（`--no-default-features`） | Apple Silicon SoC 指标：GPU 活动率 / 频率 / 功耗、温度、内存 | MIT 协议，内部直接调 IOReport，**免 sudo**；是本项目 GPU 方案的核心（见 3.3） |
| `rusqlite`（features = `bundled`） | SQLite 存储 | SQLite 编译进二进制，零外部依赖 |
| `clap` | CLI 参数解析 | 支持子命令（daemon / report / events） |
| `serde` + `serde_json` | 配置与 JSON 导出 | 报表格式之一 |
| `time` 或 `chrono` | 时间戳（ISO8601，本地时区） | 时间段查询的基础 |
| `core-foundation` + 少量 FFI | IOKit 电源事件通知 | `IORegisterForSystemPower` + CFRunLoop，免 sudo |
| `libc` | FFI 基础 | — |

> 说明：并发采用标准库线程 + `mpsc` channel，不引入 tokio——采集工具线程模型简单，减少依赖与开销。
>
> 主题：catppuccin 为内置调色板常量（自定义 `Style`），无需额外 crate。

### 3.3 GPU 数据源调研结论（重点）

Apple Silicon 的 GPU 遥测有三个候选来源，调研结论如下：

| 方案 | 是否需要 sudo | 数据内容 | 结论 |
| --- | --- | --- | --- |
| **IOReport（私有框架，libIOReport.dylib）** | **不需要** | GPU 活动率（DVFS residency）、频率、功耗、CPU/ANE 功耗、内存带宽 | ✅ **主方案**。powermetrics 内部使用的就是同一数据源；已有 Rust 实现（macmon）与多语言参考（actop / Netdata / OSHI） |
| `powermetrics` 命令行 | 需要 | `GPU Busy %`、GPU 功耗、频率、热状态 | ⚠️ 兜底方案：`sudo powermetrics --samplers gpu_power,cpu_power,thermal -i 2000 -f json`，作为 `--gpu-sudo` 可选模式 |
| 逐进程 GPU 归因 | 公共 API **不可用** | — | ❌ 本期不做。已在本机 Xcode SDK 的 `libproc.h` 中验证无 `ri_gpu_time` 字段；活动监视器的逐进程 GPU 走私有接口，actop 等项目也将此项列为需 root 的开放事项 |

**设计决策**：

1. GPU 指标以 **IOReport 免 sudo 方式**采集，通过 `macmon` 库封装（若 `macmon` 维护中断或 API 不满足，则按 actop 的 ctypes 绑定思路自写少量 FFI：订阅 Energy Model 与 GPU Performance States 两个 channel group，快照做 delta 计算）；
2. 提供 `--gpu-sudo` 可选模式调用 `powermetrics` 作为对照/兜底（用户可自行决定是否授权）；
3. 逐进程 GPU 归因记录为 **P2 实验项**（如未来公共 API 或私有接口验证可行再接入，schema 中预留 `gpu_ms` 字段）。

### 3.4 备选方案回顾

- **powermetrics 直接驱动（asitop 模式）**：实现简单但必须 sudo，长时间挂在终端会被权限打断，且与"工具自身低开销"目标冲突，**弃用为主方案**。
- **温度读取**：优先使用 `macmon` 自带 SMC 温度读取（免 sudo）；如不可用，参考 actop/mactop 的 AppleSMC（IOKit `AppleSMC` 服务，Tp\*/Te\*/Tg\* 键）实现。

### 4.2 线程模型

```text
┌─────────────────────────────────────────────────────────┐
│ 主线程（TUI 事件循环，默认 1s 刷新）                       │
│  └─ 接收 mpsc 采样结果 → 更新界面 / 转发给写入线程          │
├─────────────────────────────────────────────────────────┤
│ 采样线程（独立，1–2s 周期）                               │
│  ├─ sysinfo：进程 CPU/内存（进程表间隔可配置，默认 2s）    │
│  ├─ macmon/IOReport：GPU/功耗/温度（系统指标，默认 1s）    │
│  └─ 组装 Sample 结构体 → 发送到 channel                   │
├─────────────────────────────────────────────────────────┤
│ 写入线程                                                   │
│  └─ 消费 channel → 批量 INSERT（每 N 条一次事务）           │
├─────────────────────────────────────────────────────────┤
│ 电源事件线程（CFRunLoop）                                  │
│  └─ IORegisterForSystemPower 回调 → 写入 power_events     │
└─────────────────────────────────────────────────────────┘
```

采样线程与 TUI 通过 channel 解耦：TUI 卡顿不影响采样落库；`daemon` 模式下不启动 TUI 线程，仅采样 + 写入。

### 4.3 数据流

```text
进程表(sysinfo) ─┐
SoC 指标(macmon) ─┼─► Sample ──► channel ──► [TUI 实时展示]
电源事件(IOKit)  ─┘                       └──► SQLite（WAL）
                                                │
                                          report 子命令 ──► 聚合结果（table/csv/json/md）
```

## 5. 数据模型（SQLite）

```sql
PRAGMA journal_mode = WAL;

CREATE TABLE IF NOT EXISTS sessions (
  id         INTEGER PRIMARY KEY,
  started_at TEXT NOT NULL,          -- ISO8601，本地时区
  ended_at   TEXT,
  hostname   TEXT,
  model      TEXT,                   -- 芯片型号，如 Apple M4
  note       TEXT
);

CREATE TABLE IF NOT EXISTS system_samples (
  id              INTEGER PRIMARY KEY,
  session_id      INTEGER NOT NULL REFERENCES sessions(id),
  ts              TEXT NOT NULL,
  power_state     TEXT,              -- awake / asleep / dark_wake(推断)
  cpu_total_pct   REAL,              -- 系统总 CPU 占用
  cpu_active_ratio REAL,
  cpu_power_w     REAL,
  gpu_active_ratio REAL,             -- GPU 活动率 0–1（本次新增）
  gpu_freq_mhz    REAL,
  gpu_power_w     REAL,
  ane_power_w     REAL,
  package_power_w REAL,
  cpu_temp_c      REAL,
  gpu_temp_c      REAL,
  thermal_state   TEXT,              -- Nominal / Fair / Serious / Critical
  ram_used_bytes  INTEGER,
  swap_used_bytes INTEGER
);

CREATE TABLE IF NOT EXISTS process_samples (
  id         INTEGER PRIMARY KEY,
  session_id INTEGER NOT NULL REFERENCES sessions(id),
  ts         TEXT NOT NULL,
  pid        INTEGER NOT NULL,
  name       TEXT NOT NULL,
  cpu_pct    REAL,
  mem_bytes  INTEGER,
  gpu_ms     INTEGER                 -- 预留：逐进程 GPU 实验项
);

CREATE TABLE IF NOT EXISTS power_events (
  id         INTEGER PRIMARY KEY,
  session_id INTEGER NOT NULL REFERENCES sessions(id),
  ts         TEXT NOT NULL,
  event_type TEXT NOT NULL,          -- sleep / wake / assertion_changed / thermal
  detail     TEXT
);

CREATE INDEX IF NOT EXISTS idx_sys_ts  ON system_samples(session_id, ts);
CREATE INDEX IF NOT EXISTS idx_proc_ts ON process_samples(session_id, ts);
CREATE INDEX IF NOT EXISTS idx_pwr_ts  ON power_events(session_id, ts);
```

报表聚合示例：

```sql
SELECT pid, name,
       COUNT(*)                       AS samples,
       ROUND(AVG(cpu_pct), 1)         AS avg_cpu,
       MAX(cpu_pct)                   AS peak_cpu
FROM process_samples
WHERE session_id = ? AND ts BETWEEN ? AND ?
GROUP BY pid, name
ORDER BY avg_cpu DESC
LIMIT ?;
```

## 6. 关键设计

### 6.1 采样循环与 delta 计算

- `sysinfo` 的 CPU 占用是"两次 refresh 之间"的增量，因此采样线程维护上一次的累计时间，每个周期计算 delta；
- 进程表默认每 2s 采样一次（Top 15），系统指标默认每 1s 采样一次；两个间隔均可配置；
- 每次采样附加单调时钟（`Instant`）与墙上时钟（ISO8601），墙上时钟用于报表时间段，单调时钟用于 delta 计算，避免时钟跳变污染数据；
- 采样线程内部用 `try_send` 丢帧策略：TUI 刷新慢时丢弃中间帧，确保写入线程不积压。

### 6.2 GPU 采集与降级策略

- **主路径**：`macmon`（IOReport）读取 `gpu_active_ratio`（活动率 0–1）、`gpu_freq_mhz`、`gpu_power_w`，与 CPU/ANE/整机功耗、温度一并入 `system_samples`；
- **降级路径**：若 IOReport 初始化失败（例如未来 macOS 变更或 Intel 机器），GPU 字段写 NULL，TUI 显示 `GPU: N/A`，**不影响 CPU 采集**；
- **对照路径（可选）**：`--gpu-sudo` 时启动 `powermetrics` 子进程解析 JSON，用于交叉验证 IOReport 数据；
- `macmon` 的 `Sampler` 需要"阻塞一个完整采样窗口"，因此它运行在独立采样线程中（与 4.2 一致）。

### 6.3 电源事件与 Dark Wake 识别

- **睡眠 / 唤醒**：IOKit `IORegisterForSystemPower` 注册通知（无需 root），在 CFRunLoop 线程中接收 `kIOMessageSystemWillSleep` / `kIOMessageSystemHasPoweredOn`，写 `power_events`；收到睡眠通知时记录**精确时间戳**并 flush 睡眠前最后一批采样快照，唤醒后补记唤醒时间——两者共同构成"本次睡眠时长"；
- **断言快照**：每 60s 执行 `pmset -g assertions`，仅当输出摘要变化时落库（`assertion_changed`），用于发现阻止睡眠的进程；
- **Dark wake 推断**：macOS 没有公开的 dark wake 通知，采用间接推断——以最近一次睡眠/唤醒事件为边界，若系统仍处于"唤醒但显示关闭"窗口内且采样到持续非零 CPU/GPU 活动，则将对应样本标记为 `dark_wake`（结合可选 `pmset -g log` 尾部解析提高准确率）；
- **真睡眠时**：系统挂起，采样自然中断（表现为时间线空洞），这是正确行为；报表按电源事件把时间线切成"段"，只对每段内部做聚合。

### 6.4 TUI 布局与交互

```text
┌─ neko-perf ── 会话 3 ── 已运行 02:31:04 ── 采样 9,064 ──────────────┐
│ 电源: awake   CPU: 12.4%   GPU: 3.1%   温度: 48°C   DB: ~/perf.db │
├────────────────────────────────┬──────────────────────────────────┤
│  PID   NAME          CPU%   MEM │  CPU ──────────────             │
│ 1234  WindowServer   18.2   1.2G│  GPU ──                        │
│ 2310  coreaudiod      8.1  240M │  MEM ───────────                │
│  ...                            │  PWR ────────                  │
├────────────────────────────────┴──────────────────────────────────┤
│ 20:00:01 sleep   (assertion: WindowServer PreventUserIdleSystemSleep)│
│ 20:05:33 wake                                                     │
└────────────────────────────────────────────────────────────────────┘
```

- 顶部状态栏：电源状态、CPU/GPU 实时值、温度、数据库路径；
- 左侧：进程 Top N 表，`s` 切换排序（CPU% / MEM / PID），`/` 过滤；
- 右侧：CPU / GPU / 内存 / 功耗趋势曲线（ratatui `Sparkline` + 自定义 block chart）；
- 底部：电源事件日志；
- 主题：catppuccin（默认 mocha，`t` 在 latte / frappe / macchiato / mocha 间切换）；
- 启动流程：进入 TUI 后先显示采样间隔设置表单（默认值 + 自由输入，如 5s / 10s），确认后开始记录；
- 键位：`Space` 暂停采样、`t` 切换主题、`q` 退出（退出前 flush 并写 `ended_at`）、`?` 帮助。

### 6.5 历史检查模式（inspect）

停止记录后运行 `neko-perf inspect --db <path>`，以 TUI 方式浏览已记录数据：

- **时间段选择**：输入起止时间，或步进翻页（上一段 / 下一段 / 跳转到某个时间点）；
- **系统视图**：CPU / GPU / 内存 / 功耗曲线 + 电源事件时间线（睡眠段、dark wake 段高亮标注）；
- **进程视图**：时间段内 Top 进程表；选中某进程后展示它在该时间段内 CPU / 内存随时间的变化曲线与统计（平均、峰值、活跃样本占比）；
- 数据全部来自 SQLite 查询，复用实时 TUI 的曲线 / 表格组件；
- 支持从检查界面一键导出当前时间段的 CSV。

### 6.6 报表聚合逻辑

1. 按时间段查询 `power_events`，把时间线切为"段"（sleep 段 / wake 段 / dark wake 段）；
2. 对每个段内的 `process_samples` 做分组聚合（平均 / 峰值 CPU、活跃样本占比、总时长）；
3. 输出每段的 Top 进程 + 电源事件摘要；`--format` 支持 `table / csv / json / md`；
4. 报告头部附带系统指标摘要（该段平均 GPU、功耗、温度）。

### 6.7 数据量估算与落盘策略

- 按 1s 系统采样 + 2s 进程采样（Top 15）估算，24 小时约：
  - `system_samples`：86,400 行 ≈ 6–10 MB；
  - `process_samples`：432,000 行 ≈ 40–70 MB；
- 优化：进程表写入按批事务（每 50 条一次）、`PRAGMA synchronous=NORMAL`、WAL 自动 checkpoint；
- 提供 `--process-interval` 参数，可进一步降频（如 5s）控制体积。

## 9. 风险与限制

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| IOReport 是私有框架，未来 macOS 版本可能变更 | GPU/功耗/温度数据失效 | 抽象 `SocDataSource` trait；macmon 持续维护可跟随；失败时优雅降级为 N/A，不影响 CPU 主功能 |
| 逐进程 GPU 归因无公共 API | 无法直接回答"哪个进程在吃 GPU" | 系统级 GPU + 进程级 CPU 时间对齐推断；列为 P2 实验项 |
| `powermetrics` 需要 sudo | 长期运行被权限/密码打断 | 仅作为可选对照模式，默认免 sudo 的 IOReport 路径 |
| 真正睡眠期间无法采样 | 时间线空洞 | 属预期行为；用电源事件分段，报告按段聚合 |
| TUI 依赖终端尺寸/字符集 | SSH 或小窗口显示异常 | `daemon` headless 模式兜底；TUI 自适应布局 |
| 采样数据量随运行时长增长 | DB 膨胀 | 6.7 的落盘策略 + 可配置进程采样间隔 |

## 11. 实现进度（2026-08-29）

已实现并通过冒烟测试：

- **M1**：进程采样（sysinfo）+ SQLite 落库（WAL、分表、索引）+ `daemon` 后台模式；
- **M2**：ratatui TUI——启动间隔设置表单、实时进程表、CPU/GPU/内存/功耗 sparkline、事件日志、`q/空格/s/t//` 键位；
- **M3**：IOKit 电源事件（`IORegisterForSystemPower`，CFRunLoop 正确使用 default/common 模式）+ `pmset -g assertions` 快照；
- **M4**：macmon/IOReport 免 sudo GPU 活动率、频率、功耗、温度；采样失败优雅降级为 N/A；
- **M5**：`inspect` 历史检查 TUI（时间窗口平移/缩放、进程聚合表、单进程曲线）+ `report`（table/csv/json/md）+ `sessions`/`events`。

新增（2026-08-29 晚）：

- **统一 TUI 主菜单**（`neko-perf` 无参数进入）：开始新记录 / 历史会话回放（会话列表 → inspect）/ 设置；
- **设置界面**：主菜单与录制中（`o` 键）均可打开，持久化到 `~/Library/Application Support/neko-perf/config.toml`；录制中修改间隔 / Top N 通过 `RuntimeConfig` 原子量**立即生效**，GPU / 数据库路径下次录制生效；
- 所有子命令（record / daemon / inspect / report / sessions / events）原样保留。

补充修复（2026-08-29）：

- **进程 CPU 全 0**：sysinfo 的 `refresh_cpu_usage()` 不刷新进程 CPU，改为 `refresh_processes(..., true)`；
- **工具自耗 100%**：电源事件线程 `CFRunLoopRunInMode` 忙轮询，改为阻塞式 `CFRunLoopRun()` + 0.5s 定时器，空闲自耗降至 ~0.4%；
- **内存口径**：与活动监视器不一致（sysinfo 含 speculative、不含 inactive、不区分 App/Wired/Compressed），改为 `host_statistics64` + `vm.swapusage` 直接计算活动监视器同款口径，新增 App / Wired / Compressed / Inactive / Free / Swap 总量明细（旧库自动迁移补列）。

验证结果：本机（Apple M4）daemon 冒烟 18 秒，`system_samples` 23 行含 GPU 活动率（均值 37.6%）、功耗（6.25W）、温度（61°C）；单元测试 3 项通过，clippy 全绿，release 单二进制约 3 MB。

M6 待办：整晚长跑验证、launchd 开机自启示例、可选 `--gpu-sudo` powermetrics 对照模式。
